## Summary

The change implements the Population Globe end to end: a static Vite/React SPA that renders a `react-globe.gl` choropleth of world population from a committed, versioned snapshot, with a search box, population legend, first-use hint, and a detail panel that shows a country's population plus its ethnic/linguistic/religious breakdown and a derived diversity indicator with provenance. The architecture matches the plan (pure logic in `src/lib/`, presentational components, bundle-time dataset), input is validated on load, there are no secrets, and the local typecheck/unit/dataset gates are green (38/38 unit+component, `tsc` clean, `validate:dataset` passes). Overall quality is good for an MVP, but several test-plan claims are not backed by tests and one success criterion is measured against the wrong denominator, so I cannot sign off yet. No pull request or CI run exists for this branch (`delivery-status.md`: Delivery Status NONE), so this is a pre-PR branch review.

## Findings

- [MAJOR] tests/e2e/performance.spec.ts:61-67 — The test titled "at least 95% of boundary countries are shaded" asserts `shaded / total ≥ 0.95` where `total` is the number of Natural Earth boundary features (177), not "countries in the dataset" as SC-003 states. The dataset has 250 countries and only 215 (86.0%) carry a population figure, so the literal SC-003 (95% of dataset countries shaded) is not met; the measured value is 169/177 = 95.5% by boundary feature. `data/README.md:41-42` compounds this by claiming "175 … matched, of which 96.6%", while the snapshot's own `boundaryId` join yields 174 matched and 95.5%. — Decide the SC-003 denominator with the spec owner, encode it in `test-plan.md`/the test name, and correct the README figures (or raise population coverage) so the assertion proves SC-003 rather than a different metric.
- [MAJOR] src/lib/dataset.ts:1-213 — `parseSnapshot`, `loadSnapshot`, `countryByCode` and `sourceById` have no unit tests at all (grep for those names under `tests/` returns nothing), even though `test-plan.md` assigns "`dataset.ts` selectors and unavailable-value guards (FR-008, SC-003)" to the Unit layer and tasks T018/T019 create these modules. The untrusted-JSON validation path (bad version, missing source/year, dangling `sourceId`, duplicate `code`, invalid share/indicator range) is exactly the security-relevant boundary and is currently unexercised. — Add `tests/unit/dataset.test.ts` covering a valid fixture, each rejection branch, and the selectors.
- [MAJOR] src/components/GlobeView.tsx:63-73 — A failed/blocked `countries-110m.topo.json` fetch is swallowed (`catch(() => {})`), producing a globe with no polygons and no error, while FR-014 and the spec edge case require "a clear error state with a retry action if population data cannot be loaded **or rendered**". `tests/e2e/error-retry.spec.ts` only blocks `snapshot.json`, so this mode is untested. — Surface the boundary failure into App state (or an in-globe error with retry) and add an E2E case that blocks `**/data/countries-110m.topo.json`.
- [MAJOR] tests/e2e/search.spec.ts:12-19, tests/e2e/globe.spec.ts:17-33 — Acceptance scenarios that are only smoke-checked, so they are not actually proven: US3-2 ("the globe focuses on that country") asserts only `detail-panel` text and never that the camera moved; US1-2 asserts the globe is still visible after a drag rather than that it rotated/kept shading; US1-4 "keeps the current selection" never makes a selection before zooming. — Add an observable focus/rotation signal (e.g. expose camera lat/lng or the resolved selection in a `data-*` attribute) and assert it; select a country before the zoom assertion.
- [MINOR] src/components/GlobeView.tsx:34-53 — `centroidLatLng` averages raw coordinates, so countries spanning the antimeridian get a wrong focus point (e.g. Fiji's islands at ≈177°E and ≈−178°W average to near 0°). Search "focuses the chosen country" (FR-006) would send the camera to the wrong side of the globe for these. — Use a bounding-box centre with longitude unwrapping, or defer to a maintained centroid helper, and cover at least one antimeridian country.
- [MINOR] src/App.tsx:123, src/components/GlobeView.tsx:12,164 — `onHover` is dead plumbing: `GlobeView` computes the hovered country and calls the prop, but App passes `() => undefined`, and the spec's US1 narrative says hovering *or* selecting reveals name/population. No tooltip/hover state exists. — Either implement a hover readout (label/tooltip) or remove the unused prop so the gap is explicit.
- [MINOR] tests/ — `test-plan.md` lists `ErrorState` retry and `DataUnavailable` under the Component layer, but there are no component tests for either (`grep` under `tests/` finds neither). Their behaviour is only covered indirectly through `error-retry.spec.ts` E2E. — Add small RTL tests for the retry callback and the explicit unavailable copy.
- [MINOR] package.json:7-18, repo root — There is no lint or format command (no ESLint/Prettier/Biome config), so the review has no static-style gate to run beyond `tsc`. — Add a lint script and wire it into `test:all`/CI.
- [MINOR] src/components/SearchBox.tsx:31-38 — The input is declared `role="combobox"` with a `listbox`, but there is no keyboard navigation (`aria-activedescendant`, ArrowDown/Enter/Escape) and `aria-controls="pg-search-results"` points at a missing element when there are no results. — Implement the standard combobox keyboard pattern or drop the ARIA roles.
- [MINOR] specs/001-population-globe/research.md:34-40 — `research.md` chose UN WPP as the primary population source (World Bank only as fallback), but `fetch-dataset.ts` uses World Bank exclusively; `data/README.md` documents only the diversity-indicator deviation as "the one deliberate deviation". — Document the population-source deviation alongside the indicator one, or update `research.md`.
- [NIT] git 620f5df — `chore(001-population-globe): implement work in progress` is WIP-phrased and uses a different scope (`001-population-globe`) than the feature commit (`population-globe`). — Squash/reword before opening the PR so the Conventional Commit history is clean.
