The change implements the Population Globe as a static Vite/React SPA: a `react-globe.gl` choropleth over a committed, versioned snapshot, plus search, a population legend, a first-use hint and a detail panel that shows population and the ethnic/linguistic/religious breakdown with a derived diversity indicator and provenance. The previous review's four MAJOR findings are genuinely addressed — the snapshot validator/selectors now have 31 unit tests, a blocked boundaries fetch surfaces a retryable error, E2E now asserts camera focus/rotation, and SC-003 is defined against the rendered Natural Earth features and proven by a committed coverage test. The architecture, input validation and local gates are in good shape, but the review cannot approve yet: the dataset generator silently drops a large share of the Factbook figures (so several displayed breakdowns are materially wrong), and the production bundle uses absolute asset paths that will render a blank page on the GitHub Pages project site the deploy workflow targets. ## Findings

- [MAJOR] scripts/fetch-dataset.ts:74-84 — `parseShares` silently drops every Factbook group whose share is a range (`Russian Orthodox 15-20%`) and every group prefixed by "more/less than" (the `less than|more than|over|under` filter on line 82). This produces materially incomplete breakdowns that the app renders as if complete: `data/snapshot.json` has `RUS/religious` summing to 2.0% (a single "other Christian 2" row), `IRQ/ethnic` as only "other 5%", `TWN/ethnic` as only "indigenous 2.3%", `SSD/ethnic` as only "Nuer 15%". Across the committed snapshot 30 of 508 dimension groups sum below 90% or above 110% (e.g. `AND/religious`=10.5%, `COD/religious`=6.8%, `TKL/linguistic`=182.5%). This violates FR-004/FR-007 (the breakdown shown is not the country's composition) and, because the fractionalisation indicator is derived from these rows, poisons `diversityIndicator` wherever it survives the `ethnic.length >= 2` guard. — Parse range values (midpoint or "15-20"→15) and +/- modifiers, or mark a dimension explicitly unavailable when parse coverage is implausibly low; regenerate `data/snapshot.json`; and add a committed data-quality test or validator threshold that fails on the extreme cases rather than logging warnings.
- [MAJOR] scripts/validate-dataset.ts:52-55 — Every share-sum problem is a warning, so `bun run validate:dataset` exits 0 and CI (`.github/workflows/ci.yml`) is green even for `RUS/religious` summing to 2.0%. A validator that cannot fail on 2%-summing compositions does not protect the displayed dataset. — Escalate gross deviations (e.g. outside 50–150 or dimension groups with a single row below some floor) to errors, or assert the parser's row/share coverage in a test, so the defect above cannot ship silently.
- [MAJOR] vite.config.ts:41-45 — The build emits absolute asset URLs (`dist/index.html`: `<script ... src="/assets/index-….js">`), but `.github/workflows/deploy.yml` publishes to GitHub Pages, where a project site is served from `https://rayedbajwa.github.io/human-population-calculator/`. Absolute `/assets/...` resolves to `https://rayedbajwa.github.io/assets/...` → 404 → blank page; the E2E suite cannot catch this because `vite preview` serves at the domain root. — Set `base: './'` (or the repo subpath) in `vite.config.ts` and re-check `dist/index.html` and the relative `data/snapshot.json` fetch.
- [MAJOR] specs/001-population-globe/delivery-status.md — `Delivery Status: NONE` (0 pull requests); T056 has not been executed, so there is no PR and no CI run to review against and the pipeline's "PR + CI → code review" precondition is unmet. — Push `001-population-globe`, open the PR into `main`, and let CI (`lint → typecheck → unit → build → E2E`) run; re-review once checks are visible.
- [MINOR] tests/e2e/reduced-motion-touch.spec.ts:5-10 — The test is named "renders the globe with auto-rotation disabled" but only asserts the globe and hint are visible; it never observes that the camera is stationary. `test-plan.md:51` claims this edge is covered. — Poll `data-camera-lng` under `reducedMotion: reduce` and assert it does not change (or expose/report the controls' `autoRotate` state).
